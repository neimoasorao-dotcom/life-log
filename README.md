# life log

日々の時間を、そっと記録する個人用ライフログ。React / TypeScript / Viteで作った、スマートフォン優先のWebアプリです。

## 起動

Node.js 22.12以降（または20.19以降）が必要です。

```sh
npm ci
npm run dev
```

クラウド環境では、npmキャッシュに書き込み可能な場所を指定してください。

```sh
cd /workspace/life-log
npm ci --cache /workspace/.npm-cache
npm run dev -- --port 5173
```

## 使い方

- **記録**：カテゴリーをタップして開始。別のカテゴリーでメイン記録を終了・切り替え。「同時記録」で現在の記録を継続しながら追加。それぞれの「終了」で保存します。同時記録への自動復帰はありません。
- **今日**：日付を選び、一日のタイムラインを確認。重なる記録は横に並びます。ブロックをタップして編集・削除、「＋」で手動追加します。日付を含めて編集できるため、日付跨ぎも記録できます。基本表示は6:00〜24:00、6時以前の記録がある日は0時から表示します。
- **分析**：今日・今週（月曜始まり）・今月を切り替え、カテゴリー合計、勉強・学習時間、記録済み・未記録時間、勉強時間の推移を確認。矢印で過去の期間も表示できます。
- **設定**：曜日テンプレートの追加・編集・削除、カテゴリーの追加と名前・アイコン・色の編集、JSONバックアップの書き出し・読み込みができます。

最初は空の記録で始まります。サンプルデータは混在しません。

## GitHub Pagesへの公開

クラウド環境内で実装・起動しただけでは、GitHub Pagesのサイトは更新されません。公開するには、ソースコードとロックファイル、`.github/workflows/deploy-pages.yml` をGitHubに反映する必要があります。

1. GitHubのリポジトリで **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定します。
2. 実装一式を `main` に反映します。Actionsの **Deploy life log to GitHub Pages** がテストとビルドを実行し、`dist` を公開します。必要なら **Run workflow** から再実行できます。
3. ワークフローの `deploy` が成功した後、`https://neimoasorao-dotcom.github.io/life-log/` を開きます。

READMEだけが表示される場合は、READMEを配信する旧設定のままか、アプリの公開がまだ完了していません。公開完了後も古い画面が残るときは再読み込みしてください。ブラウザの保存データを削除する必要はありません。

公開ビルドは `VITE_BASE_PATH=/life-log/` を指定し、JavaScript・CSS・アイコンのパスをサイトの配置先に合わせます。ローカル開発は従来どおりルートパスです。

```sh
VITE_BASE_PATH=/life-log/ npm run build
VITE_BASE_PATH=/life-log/ npm run preview -- --port 4173
```

上記のプレビューでは `/life-log/` を表示して確認します。

## 保存・時間の仕様

- IndexedDBに保存し、保存完了後に操作を反映します。保存エラー時は通知し、元のデータを保持します。トランザクションで最新データを読み取り、複数タブによる記録の上書きを防ぎます。
- タイマーは開始時刻と現在時刻の差分から計算。再読み込みやバックグラウンド復帰でも復元されます。
- 曜日テンプレートは登録日から各該当日に生成。アプリを開いたとき・開いている間の分更新で生成し、閉じていた期間も補完します。サーバーやOSのバックグラウンド処理は使用しません。
- テンプレートの発生日を保存するため、その日の記録を削除しても再生成されません。個別編集はテンプレートを変更しません。テンプレートの編集・削除は、生成済みの記録に影響しません。
- テンプレートは当日分を終了時刻まで生成し、未来部分は薄く表示。分析は現在時刻までの実績だけを集計します。
- 活動時間は0:00〜24:00の各カテゴリーの時間をそれぞれ加算。記録済み時間は6:00〜24:00内の区間の和集合（重複を除去）。未記録時間はこの範囲の経過時間との差分。未来の時間は含みません。
- 日付と曜日は利用端末のローカルタイムゾーンで扱い、日付跨ぎの記録は各日へ分割して集計します。
- ブラウザデータの削除・端末変更ではローカルデータを引き継げません。設定から定期的にバックアップを書き出してください。読み込みは確認後に現在のデータを置き換えます。

## 構成

- `src/lib/types.ts`：カテゴリー・記録・テンプレートのデータ型
- `src/lib/model.ts`：開始・終了・編集・テンプレート生成
- `src/lib/time.ts`：ローカル日付と時間計算
- `src/lib/analytics.ts`：独立した集計・区間統合・タイムラインレーン配置
- `src/lib/storage.ts`：IndexedDBとデータ検証。将来の同期用アダプターを置ける境界
- `src/lib/useAppData.ts`：保存とUI状態の連携
- `src/pages/`：4つの画面
- `src/components/`：カテゴリーアイコン、ダイアログ、記録フォーム

## 検証

```sh
npm test              # データモデル、重複集計、日付跨ぎ、テンプレート例外、保存
npm run build         # TypeScript + 本番ビルド
npm run test:e2e -- --project=chromium-mobile  # モバイルChromium
npm run test:pages    # /life-log/ 配下の本番ビルド・アセット・記録の復元
```

Playwrightのブラウザを取得できる環境では、WebKitによるiPhoneサイズの検証も実行できます。

```sh
npx playwright install chromium webkit
npm run test:e2e
```

システムの`/usr/bin/chromium`がある場合は利用します。別の場所なら`CHROMIUM_EXECUTABLE_PATH`で指定できます。クラウドでブラウザをダウンロードする場合は`PLAYWRIGHT_BROWSERS_PATH=/workspace/.playwright-browsers`を指定してください。

MVPではログイン・クラウド同期・通知・タグ・評価・睡眠記録は実装していません。今後はストレージ境界を使った同期と、独立した集計ロジックによる曜日別・時間帯別分析を追加できます。
